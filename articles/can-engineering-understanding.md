# CAN通信在机器人中的工程理解

## 为什么记录
CAN是机器人系统中非常常见的通信方式。

学习CAN不能只停留在帧格式，而应该理解它在整个机器人架构中的作用。

## CAN在机器人中的位置

典型结构：

```
计算平台
   |
 CAN总线
   |
控制板
   |
电机驱动
```

## 核心理解

CAN的优势：

- 多节点通信
- 抗干扰能力强
- 总线结构简单
- 工业应用成熟

## 工程调试思路

遇到CAN没有数据时：

第一步：检查硬件

- 供电
- CANH/CANL连接
- 共地
- 终端电阻

第二步：检查通信参数

- 波特率
- ID
- 数据长度

第三步：检查软件

- 驱动
- 接收缓存
- 协议解析

## 我的总结

机器人通信问题很多时候不是代码问题，而是系统问题。

排查应该从物理层逐渐向应用层推进。
